## Architectural decisions from this review

1. Remove `RunPolicy` and all experiment/task fields from `ProjectIR`.
2. Separate visible `TaskInstructions`, mechanical `KernelSafetyContext` with genuine `UserLock` records, hidden `EvaluationSpec`, and trusted `ExperimentConfig`.
3. Keep hidden grading data out of agent inputs, read tools, kernel inputs/errors, workspace artifacts and public provenance. Independently evaluate frozen submissions without feedback during the paired run.
4. Check structure throughout a transaction; check genuine locks against the completed transaction; assess experiment editorial criteria after submission without vetoing edits or discarding bad outcomes.
5. Allow baseline reasoning, retrieval, informal planning, multi-step edits and recovery under the same total resource limits. The structured contract/plan/compiler architecture is the treatment.
6. Use controlled 25 fps CFR / 48 kHz fixtures, explicit frame alignment, measured timing and cumulative timing tests initially.
7. Retain minimum local reproducibility/history; defer production persistence and concurrency mechanisms.

The architecture document's hard-protection invariant is interpreted as a real, explicitly created user lock. A natural-language preservation request or hidden evaluator annotation does not create such a lock. ## Time, identity and timeline model

Use safe integer milliseconds, half-open ranges `[startMs, endMs)`, normalized presentation origin and unit playback speed. Initially use controlled 25 fps CFR fixtures: one frame is exactly 40 ms; 48 kHz audio has 1920 samples per frame. Clip boundaries, timeline positions and playable endpoints lie on this grid, keeping nominal arithmetic exact without rational timeline units.

Transcript cues can remain off-grid millisecond speech ranges. They describe speech, not legal cut positions. Both conditions receive the same public grid guidance. Before kernel execution, deterministically align proposed source boundaries and timeline destinations to the nearest frame boundary; exact half-frame ties go earlier. Preview endpoints follow the same rule. Responses and receipts record requested/effective values and rounding deltas. Reject empty/reversed aligned intervals, endpoint splits, extending trims, overlaps or source bounds violations. Never silently clamp or use hidden annotations to select alignment.

Only effective aligned integer operations enter the pure reducer. Replay those operations, retaining requested values in traces. Frame count and presentation mapping define the valid source end; rounded container duration alone does not. Reject fixture endpoints not on the supported grid rather than silently truncate. Other CFR rates and VFR require a later reviewed timing design; universal input support is not promised.

Support one source asset, one sequence and one linked audiovisual lane. Each clip maps an equal-duration source interval to a timeline interval; audio/video move together. No overlap, mixing, transitions, speed changes or independent audio edits. Gaps render black/silence. Sequence duration is the maximum clip end including gaps. Empty candidates have duration zero and can be undone, but cannot render or be promoted.

Asset IDs derive from source-byte hashes; segment IDs from asset ID, transcript digest, cue index and normalized range. Source segment identity survives timeline edits. Timeline clip identity is separate. Splits retire the parent and return deterministic child IDs derived from operation identity/output position; callers retrieve updated IDs. IDs contain no condition or evaluator labels.

## Proposed TypeScript/Zod contracts

This is schema design only. Core owns mechanical objects; Tools/CLI own visible task/orchestration objects; the evaluator/runner entry point owns hidden schemas. Do not put all schemas into Core or the agent runtime. Parse external requests and persisted objects strictly and infer TypeScript types from them.

```ts
import { z } from 'zod';

const Id = z.string().min(1);
const UInt = z.number().int().nonnegative().max(Number.MAX_SAFE_INTEGER);
const PositiveInt = UInt.refine(value => value > 0);
const Ms = UInt;
const Digest = z.string().regex(/^[a-f0-9]{64}$/);
const Range = z.object({ startMs: Ms, endMs: Ms }).strict()
  .refine(value => value.endMs > value.startMs);
const SourceRef = z.object({ assetId: Id, range: Range }).strict();
const DurationTarget = z.object({ minMs: Ms, maxMs: Ms }).strict()
  .refine(value => value.minMs <= value.maxMs && value.maxMs > 0);

// Core: no task or experiment metadata.
const SourceAsset = z.object({
  id: Id, contentHash: Digest, mediaPath: z.string().min(1),
  durationMs: PositiveInt, frameCount: PositiveInt,
  video: z.object({
    streamIndex: UInt, width: PositiveInt, height: PositiveInt,
    fpsNumerator: z.literal(25), fpsDenominator: z.literal(1),
  }).strict(),
  audio: z.object({
    streamIndex: UInt, sampleRate: z.literal(48000), channels: PositiveInt,
  }).strict().optional(),
  presentationOriginUs: z.number().int()
    .min(Number.MIN_SAFE_INTEGER).max(Number.MAX_SAFE_INTEGER),
}).strict();
const MediaSegment = z.object({
  id: Id, assetId: Id, sourceRange: Range, transcriptText: z.string(),
  speaker: z.string().optional(),
}).strict();
const TimelineClip = z.object({
  id: Id, assetId: Id, sourceRange: Range, timelineStartMs: Ms,
}).strict();
const ProjectIR = z.object({
  schemaVersion: z.literal(1), id: Id,
  assets: z.array(SourceAsset).length(1), transcriptHash: Digest,
  segments: z.array(MediaSegment),
  sequence: z.object({ id: Id, clips: z.array(TimelineClip) }).strict(),
}).strict();

// Explicit user locks; no editorial grading criteria.
const OperationKind = z.enum(['split', 'trim', 'delete', 'ripple_delete', 'move']);
const UserLock = z.object({
  id: Id, createdBy: z.literal('user'),
  mode: z.literal('retain_source_coverage'),
  sourceRanges: z.array(SourceRef).min(1),
  provenanceId: Id, // trusted explicit lock action, not planner interpretation
}).strict();
const KernelSafetyContext = z.object({
  schemaVersion: z.literal(1), projectId: Id,
  allowedOperations: z.array(OperationKind),
  maxOperationsPerBatch: PositiveInt, userLocks: z.array(UserLock),
}).strict();

// Agent-visible user input, without gold bindings or criterion IDs.
const TaskInstructions = z.object({
  schemaVersion: z.literal(1), id: Id, rawRequest: z.string().min(1),
  userProvidedDurationTarget: DurationTarget.optional(),
  userProvidedSourceSelections: z.array(SourceRef),
}).strict();
const IntentItem = z.object({
  description: z.string().min(1), inferredRanges: z.array(SourceRef),
}).strict();
const EditContract = z.object({
  schemaVersion: z.literal(1), id: Id, taskId: Id,
  objective: z.string().min(1), targetDuration: DurationTarget.optional(),
  preserve: z.array(IntentItem), protect: z.array(IntentItem),
  allow: z.array(z.string()), avoid: z.array(z.string()),
  autonomy: z.enum(['propose_only', 'edit_candidate']),
  successCriteria: z.array(z.object({ id: Id, description: z.string() }).strict()),
}).strict();
const EditorialPlan = z.object({
  schemaVersion: z.literal(1), id: Id, contractId: Id, baseContentHash: Digest,
  selectedSegments: z.array(Id), removedSegments: z.array(Id),
  reorderings: z.array(z.object({
    segmentId: Id, beforeSegmentId: Id.nullable(),
  }).strict()),
  rationale: z.string(), unresolvedQuestions: z.array(z.string()),
  estimatedDurationMs: Ms,
}).strict();

const fields = { operationId: Id };
const EditOperation = z.discriminatedUnion('type', [
  z.object({ ...fields, type: z.literal('split'), clipId: Id, atSourceMs: Ms }).strict(),
  z.object({ ...fields, type: z.literal('trim'), clipId: Id, sourceRange: Range }).strict(),
  z.object({ ...fields, type: z.literal('delete'), clipId: Id }).strict(),
  z.object({ ...fields, type: z.literal('ripple_delete'), clipId: Id }).strict(),
  z.object({ ...fields, type: z.literal('move'),
    clipId: Id, destinationTimelineStartMs: Ms }).strict(),
]);
const EditBatch = z.object({
  schemaVersion: z.literal(1), batchId: Id, workspaceId: Id,
  expectedRevision: UInt, operations: z.array(EditOperation).min(1),
}).strict();
const SnapshotRef = z.object({ revision: UInt, contentHash: Digest }).strict();
const AgentWorkspace = z.object({
  schemaVersion: z.literal(1), id: Id, projectId: Id,
  base: SnapshotRef, head: SnapshotRef, safetyContextHash: Digest,
  taskId: Id.optional(), state: z.enum(['open', 'committed', 'discarded']),
  undoReceiptIds: z.array(Id), redoReceiptIds: z.array(Id),
  proposedBatches: z.array(EditBatch), previewIds: z.array(Id),
}).strict();

// Evaluator-only: never exported to tools/kernel or agent artifacts.
const EvaluationSpec = z.object({
  schemaVersion: z.literal(1), id: Id,
  sourceHash: Digest, transcriptHash: Digest, targetDuration: DurationTarget,
  retentionCriteria: z.array(z.object({
    id: Id, description: z.string(), referenceRanges: z.array(SourceRef).min(1),
    contextRanges: z.array(SourceRef),
  }).strict()),
  semanticRubric: z.array(z.object({ id: Id, description: z.string() }).strict()),
}).strict();
const ExperimentConfig = z.object({
  schemaVersion: z.literal(1), id: Id, taskId: Id, evaluationSpecId: Id,
  initialContentHash: Digest, safetyContextHash: Digest,
  model: z.object({ provider: Id, modelId: Id, version: Id }).strict(),
  sampling: z.record(z.string(), z.unknown()),
  budget: z.object({
    maxTokens: PositiveInt, maxToolCalls: PositiveInt,
    maxRepairAttempts: UInt, timeoutMs: PositiveInt,
  }).strict(),
  rendererPresetHash: Digest, evaluatorConfigHash: Digest, trialSeed: UInt,
}).strict();
const VerificationResult = z.object({
  schemaVersion: z.literal(1), checkId: Id,
  scope: z.enum(['mechanical', 'editorial']),
  kind: z.enum(['deterministic', 'model_assisted']),
  status: z.enum(['pass', 'fail', 'review']),
  evidence: z.array(z.object({
    message: z.string(), source: SourceRef.optional(), artifactId: Id.optional(),
  }).strict()).min(1),
  confidence: z.number().min(0).max(1).optional(), evaluatedContentHash: Digest,
}).strict();

type Project = z.infer<typeof ProjectIR>;
type Operation = z.infer<typeof EditOperation>;
type SafetyContext = z.infer<typeof KernelSafetyContext>;
type Task = z.infer<typeof TaskInstructions>;
type Contract = z.infer<typeof EditContract>;
type Plan = z.infer<typeof EditorialPlan>;
type Workspace = z.infer<typeof AgentWorkspace>;
type Check = z.infer<typeof VerificationResult>;
```

Core contextual checks require unique IDs, resolved references, bounded source ranges, safe computed ends, frame alignment and sorted non-overlapping clips. Ingestion validates cue order/ranges separately. Contracts/plans contain fallible inferred ranges, not gold annotations or locks. The future compiler rejects unresolved IDs, contradictory selections, ambiguous overlap or cyclic reordering without receiving evaluator truth.

ProjectIR holds content, not revision counters. A different task, lock context, rubric, budget or condition cannot change its canonical content hash. Store task/safety/optional orchestration artifacts beside snapshots. Hidden spec/config hashes appear only in trusted evaluation/run records. A common VerificationResult shape does not grant visibility: only mechanical results reach tools; editorial results remain offline. Trusted evaluator records separately bind spec/config version, snapshot/render hash and input provenance.

## Pure kernel and five operations

The internal interface receives effective aligned operations, never task/evaluation inputs:

```ts
type ApplyResult =
  | { ok: true; nextProject: Project; clipMappings: Record<string, string[]> }
  | { ok: false; error: { code: string; evidence: string[] } };
type ApplyBatch = (
  project: Project,
  operations: readonly Operation[],
  safety: SafetyContext,
) => ApplyResult;
```

Workspace handles revision checks, timing-normalization receipts and persistence. Kernel independently checks safety-context/project identity. Caller-authored replacement ProjectIR is not an editing command.

| Operation | V0.1 semantics |
| --- | --- |
| `split` | Effective source split strictly inside a clip; replace parent with deterministic children preserving coverage, total duration and timeline position; return child IDs. |
| `trim` | Effective non-empty source interval is a subset of the current interval. Keep timeline start fixed; no later-clip shift, extension or implicit ripple. Head trim changes content at the existing start; shorter duration leaves a trailing gap. |
| `delete` | Remove a clip without changing other starts. Interior deletion leaves a gap; final deletion reduces duration to the maximum remaining end. |
| `ripple_delete` | Remove a clip and shift later clips left by its duration, preserving pre-existing gaps. Split first for subrange deletion. |
| `move` | Set a clip's timeline start to its effective absolute destination; source/other clips unchanged. Reject overlap; no implicit swap, overwrite or ripple. Reorder through a temporary free interval in an atomic batch. |

Aligned example: A is source/timeline `[0,1000)`, B `[1000,2000)`, C `[2000,3000)`. Deleting B leaves C at 2000; ripple-deleting B moves C to 1000. Split A at 400 produces children at 0/400. Trim A to `[200,800)` leaves timeline start zero and duration 600. Moving C to 400 fails for overlap. Swapping A/B can move A to free start 3000, B to 0, then A to 1000, without any invalid intermediate structure.

Structural invariants apply at initialization/load, before a transaction, after every provisional operation, before publication and during undo/replay/promotion:

1. Strict schemas, unique IDs, valid references and immutable source metadata/transcript.
2. Positive source/clip durations; nonnegative safe integer times and overflow-safe computed ends.
3. Source intervals within playable extent; clip boundaries/positions aligned to the supported grid.
4. One sorted non-overlapping audiovisual lane. No malformed clip, overlap, dangling reference or out-of-bounds source even in private state.
5. Identical supported operations/mechanical limits; no caller media-path/stream/filter inputs or direct project writes.
6. Candidate/accepted isolation; published changes originate from the reducer or validated receipt-based undo/redo.

Genuine locks are a separate final-state invariant: each user-locked interval must be fully covered by the union of completed candidate source intervals. Adjacent split children count; partial retention does not. Locks refer to source coverage, not clip identity. Initial/published state must satisfy the bound genuine lock context. That context is fixed during a run; changes require a trusted explicit user lifecycle action, not a planner. Undo/redo under a changed context must fail or use a new workspace rather than bypass locks.

Natural-language duration/preservation goals are not structural invariants. Only genuinely created source-retention locks constrain transaction publication. Ordinary editorial criteria are assessed independently after submission. AETHER-derived constraints can guide its compiler's proposals but cannot become shared kernel gates or evaluator inputs.

## Transaction validation boundaries

1. Parse the request; validate workspace/revision, limits, identities and the current structurally valid state. Normalize timing without annotation input.
2. Apply each effective operation to a private copy and validate structure after each step. Failure at operation N discards all private changes; publish no snapshot, head, receipt or preview.
3. Validate completed structure and then genuine user-lock coverage. Do not treat transient clip-ID replacement as coverage loss. Private states may temporarily fail a final-state editorial lock condition, but can never corrupt project structure.
4. Publish one candidate revision and batch receipt only on success. Otherwise preserve head/content/history exactly and record a separate rejected-attempt mechanical trace.
5. Later rendering/submission/promotion checks mechanical renderability and genuine locks. Hidden target/retention criteria never gate a research submission. A mechanically valid bad edit is retained and scored.

No-op requests return a documented no-change result rather than an applied-edit receipt. Operations can refer to deterministic children created earlier in the batch. Mechanical errors cover schemas, references, bounds, alignment, overlap, stale revision, operation limits and actual user locks, with only corresponding public evidence. The kernel never receives hidden criteria, so error text or accept/reject behavior cannot expose their ranges, names, counts or status. Changing only EvaluationSpec must leave edits, responses and public traces unchanged.

## Media ingestion and rendering

Ingestion is a trusted lifecycle action, not an agent edit. Inputs: controlled local CFR video and UTF-8 timestamped transcript JSON with `{ schemaVersion: 1, timeUnit: 'seconds' | 'milliseconds', cues: [{ start, end, text, speaker? }] }`. No ASR service is required.

1. Hash source/transcript bytes and retain originals; copy source into immutable project-relative content-addressed storage. Never change user source files.
2. Run ffprobe with fixed argument arrays and `spawn`/`shell: false`. Record selected streams, dimensions, actual frame count/PTS cadence, audio rate, presentation origin and binary versions. Verify CFR from timestamps; average frame rate alone is insufficient. Reject ambiguous streams, VFR, unsupported rotation/HDR, profile mismatches, contradictory duration or uncertain A/V mapping.
3. Normalize the presentation origin while preserving relative A/V offsets. Test zero and supported nonzero origins; validate playable end against the frame grid. Do not silently transcode uncontrolled sources into experimental fixtures.
4. Convert cue times once using documented nearest-millisecond rounding; reject unordered, empty, overlapping or out-of-bounds cues. Cue gaps are legal and are not proof of silence. Create stable segments with no gold tags, task-specific segmentation or inferred locks.
5. Create the full-source initial ProjectIR. Bind separate genuine safety context/task objects as lifecycle inputs. Ingestion is independent of EvaluationSpec.

Render from a validated read-only snapshot, bounded aligned timeline range/full sequence and fixed preset. Compile source trims, timestamp resets, linked audio trims, black/silence gaps and ordered concat. Re-encode for arbitrary cuts instead of keyframe-only copying. Synthesize silence for no-audio input. Use fixed SDR resolution, 25 fps, 48 kHz, codecs and thread policy. Media alone constructs bounded FFmpeg recipes/arguments. Agents select no executable, arbitrary output path, shell string, filter or codec.

Record content/source hashes, requested/effective ranges, preset/binary versions, expected frame/sample counts, nominal duration, measured video/audio/container duration, encoder delay/padding, offsets and output digest. Previews return actual timing/mechanical evidence, never editorial scoring.

Use a lossless controlled test preset to verify exact expected frames and decoded audio samples. For delivery output, compare decoded timing to nominal with declared encoder delay/padding: full-render drift must stay within one output video frame plus one encoded audio-frame duration, independent of clip count. Record exact discrepancy/A-V offset; failure requires revising the preset/recipe before experimentation. Do not multiply tolerance by the number of edits. Offline duration evaluation records measured delivered and nominal durations; borderline timing becomes `review`.

Required accumulation tests use 1, 10 and 100 cuts, repeated off-grid requests, split/trim combinations, gaps and reordering. Generate a fixture long enough for 100 distinct legal cuts (for example, 12 seconds / 300 frames). Compare aggregate expected frames/samples to probed/decoded output; rounding must not grow with edit history. Split -> render preserves total frames; split -> undo restores content; equivalent final timelines from different histories have equivalent decoded timing. Quantize proposed boundaries once and never re-round effective positions or independently round each concat audio segment. Cross-platform encoded byte identity is not required.

## Agent Workspace and minimal reversible persistence

A workspace is an isolated local candidate branch from accepted ProjectIR. Assets/transcript are immutable/shared; heads/history are independent. It binds a visible task and separate safety context, stores proposed operations/previews and optional AETHER artifacts. No evaluator paths, gold annotations, condition mapping or hidden spec/config hash are present. Accepted state and other candidates remain unchanged by editing, rendering, undo or discard.

```text

  assets/<sourceHash>.<ext>

  transcript.json
  snapshots/<contentHash>.json

  workspaces/<workspaceId>/
    task.json

  experiment-config.json
  evaluation-spec.json
  submissions.json
  condition-map.json
  results.json
```

Use canonical immutable snapshots and before/after batch receipts containing requested/effective operations, payload digest, snapshot references, visible safety hash and clip mappings. Time/latency metadata stays outside content hashes. Write complete immutable files, then atomically replace the head on the same local filesystem. Validate references on load; torn/missing content fails closed. Orphan files are not committed state. Do not promise universal power-loss durability; unverifiable interrupted runs are invalidated and restarted.

One local owner process edits sequentially; multi-process writing is unsupported. Stale revisions fail. Trusted undo/redo restores only stored receipt content through Core validation and the fixed genuine-lock context, never model-authored IR. Content hashes restore exactly while revision counters increase. New edits clear redo. Replay effective operations from the initial snapshot and compare every receipt's after hash.

Use simple local batch-ID/payload-digest deduplication. An identical retry returns its original historical receipt; different content under the same ID fails. Refresh the head after historical results. Replayed requests count resource use, not another applied edit. Persist enough identity to reject accidental double application on explicit restart; no network exactly-once system.

Promotion is a trusted explicit command checking mechanical validity, actual locks, non-empty renderability and unchanged accepted base. It never consults hidden scores. Research submission freezes the designated workspace/render, without requiring promotion or editorial success. Keep missed-duration/caveat outputs; record empty/no-render/time-out outcomes as unsuccessful submissions rather than omit them. Offline evaluation cannot mutate candidates or trigger retries. Artifacts/checks bind their content hashes; stale evidence cannot describe a newer head.

## Shared tools and information flow

Both conditions use identical implementations, schemas, feedback, limits, timing normalization and safety context:

- `get_timeline(workspaceId)`: current clips/revision/hash, duration, gaps and bounded pagination.
- `get_task(workspaceId)`: identical visible TaskInstructions and genuine user-lock information. Replaces the original overloaded `get_contract` policy tool; no structured contract is required from baseline.
- `search_transcript(workspaceId, query, limit, cursor?)`: deterministic lexical search/excerpts/source evidence without grading labels or gold-based ranking.
- `inspect_segment(workspaceId, segmentId, contextMs?)`: segment and bounded source context, with public frame-grid guidance.
- `preview_range(workspaceId, timelineRange)`: identical bounded media preview and measured mechanical timing.
- `apply_edit_batch(EditBatch)`: five edits through the same normalization/kernel/workspace path.

Notes/rationale are optional trace metadata, never privileges. Read results are detached. Bound batch/search/context/preview requests identically. Either agent may inspect further through repeated retrieval within its total budget. Baseline informal planning lives in ordinary dialogue; AETHER contract/plan storage is its orchestration, not a condition-dependent shared read tool.

## Remaining trade-offs

1. **CFR versus broader timing.** Integer milliseconds and 25 fps grid are exact for controlled fixtures. Other rates/VFR may need rational/frame-index mapping or finer units; review/version that before such sources enter Experiment 001. No silent normalization.
2. **Alignment near speech.** Grid rounding can remove/add short speech. Record effective cuts and give both paths equal preview/rounding feedback; independent evaluation assesses meaning. Context annotations reflect rendered coverage without becoming kernel inputs.
3. **Locks versus measurement.** Real locks are useful safety behavior but confound retention scoring. Scored content is unlocked in Experiment 001. Any later locked-content experiment is separately declared; coverage is still distinct from meaning.
4. **Private structure versus final locks.** Final lock checking handles ID-changing edits/atomic combinations. Structure stays valid at every step; moves still need free-space staging rather than temporary overlap/corruption.
5. **Evaluator reliability.** Gold annotations and semantic judges can be wrong. Freeze creation/version/context procedures, use independent grading/blind questions, report uncertainty/review and keep feedback out of trials. Detailed annotation/adjudication methodology is for the later experiment plan.
6. **Strong baseline and budgets.** Equal budgets do not require equal calls: structured stages cost resources. Baseline informal planning/recovery stays allowed. Fix provider reasoning settings, practical budgets, trial counts/order/stopping rules later and record deviations.
7. **Local visibility.** Separate inputs/exports/callbacks prevent accidental model exposure; the host user still has filesystem access. Adversarial OS isolation is outside scope, but accidental prompts/tools/artifacts and grading oracles must be tested.
8. **Simple persistence.** Full snapshots cost disk; single-writer storage does not promise power-loss recovery. Validated restart/replay suffices; invalid trials are recorded rather than quietly salvaged by score.
9. **Delivery tolerance.** Padding can separate container and decoded duration. Validate preset/tolerance on real fixtures and report video/audio/container timing separately. The full-render bound stays independent of edit count; borderline duration becomes review.
