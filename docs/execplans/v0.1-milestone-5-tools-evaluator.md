## Purpose and observable outcome

After this milestone:

- **Shared tools.** A trusted host can give any agent (baseline, AETHER or grounding-only) the **same** nine tools, bound to one workspace:
  - `get_timeline`, `get_task`, `search_transcript`, `inspect_segment`, `preview_range`, `apply_edit_batch`, `write_notes`, `read_notes`;
  - `submit`, which freezes the workspace and ends the agent's turn.
- **Traces.** Every tool call is traced with its returned source ranges. Proposal 001 needs these to decide whether a criterion was ever retrieved.
- **Offline evaluator.** After submissions freeze, a separate trusted entry point grades them from an EvaluationSpec. It checks duration, retention and the all-hard-criteria pass. Semantic criteria return `review`.
- **Diagnostics.** A post-freeze pass assigns each failed criterion a failure stage: `not_retrieved`, `retrieved_not_kept` or `intended_not_executed`.
- **Proof that hidden data never leaks.** Sentinel-based noninterference tests show that nothing from the EvaluationSpec reaches any tool output, error or trace, and that changing the spec changes no agent-visible byte.

There are no live models in M5. Scripted agents exercise the tools. Live adapters, the AETHER compiler and the experiment runner come after M6.

**Out of scope**

## Package boundaries (F1)

```text
@aether/tools          (shared, agent-visible)  tool names, input/output Zod schemas, limit constants
@aether/harness        (trusted)                 createToolHost(store, workspaceId, limits) → ToolHost
@aether/harness/evaluation (trusted, separate entry) runEvaluation(evaluationRoot, projectStore, spec, config)
@aether/verification/evaluator   (trusted)       evaluateSubmission(spec, frozen) → results
@aether/verification/diagnostics (trusted)       diagnose(spec, frozenResults, traces, notes, plans?) → diagnostics
```

- `@aether/harness` depends on core, tools, workspace and media. Its main entry must **not** reach the `evaluator` or `diagnostics` subpaths, which a boundary test enforces.
- Only `@aether/harness/evaluation` may import them.
- `@aether/tools` gains no runtime dependency on workspace, so there is no cycle.

## Tool contracts (in `@aether/tools`)

Every tool takes `workspaceId` for interface parity with the parent plan. The host is bound to one workspace and rejects any other ID with `workspace_mismatch` (F2). Every result is either `{ ok: true, data }` or `{ ok: false, error: { code, message, evidence } }`, using only mechanical fields.

| Tool | Input | Output (data) |
| --- | --- | --- |
| `get_timeline` | `{ workspaceId, cursor? }` | revision, contentHash, durationMs, clips (paged, ≤ 200), gaps, frame-grid note |
| `get_task` | `{ workspaceId }` | the visible TaskInstructions + genuine user locks (ranges only) |
| `search_transcript` | `{ workspaceId, query, limit?, cursor? }` | matches `{ segmentId, sourceRange, excerpt, score }`, nextCursor |
| `inspect_segment` | `{ workspaceId, segmentId, contextMs? }` | segment text + neighbouring cues within `contextMs` (≤ 30 s) + whether each is currently on the timeline |
| `preview_range` | `{ workspaceId, timelineRange }` | requested/effective range, the transcript of the timeline in range (in timeline order), measured timing and mechanical checks, artifactId (never a path) |
| `apply_edit_batch` | `EditBatch` | outcome, receipt summary (effective ops, alignments, created/retired clip IDs), new head |
| `write_notes` / `read_notes` | `{ workspaceId, expectedRevision, text }` / `{ workspaceId }` | notes revision/text |
| `submit` | `{ workspaceId }` | frozen revision/contentHash; the session ends |

**Search (F4).** Lexical and deterministic:
- normalize to NFKC lowercase and split on non-letters and non-digits;
- score is the number of distinct query tokens present, then term frequency;
- ties go by source start, then segment ID.
- There are no embeddings, no ranking by annotations and no hidden boosts.

**Preview (F5).** Uses the `delivery-h264-v1` preset through M4 `renderPreview` and is bounded to ≤ 60 s of timeline. Agents receive text and measured timing, not media bytes. Multimodal preview is a later, arm-symmetric decision.

## Limits (F3)

`ToolLimits` is one frozen object passed to every host and recorded in the run manifest:

```text
maxTimelinePage 200 · maxSearchResults 20 · maxQueryChars 200 · maxContextMs 30000
maxPreviewMs 60000 · maxBatchOperations = safety.maxOperationsPerBatch · notesMaxBytes 16384
maxToolCalls (from ExperimentConfig.budget) · per-call timeout 120 s
```

- Exceeding a limit gives `limit_exceeded`.
- The tool-call budget is counted by the host, and replayed (deduplicated) batches count too (parent plan).
- Once the budget is exhausted, every call returns `budget_exhausted` and the host auto-submits the current head. The submission records `outcome: budget_exhausted`, so it is still evaluated, not dropped (parent: "record unsuccessful submissions rather than omit them").

## Tracing (F6)

- Per workspace, the store gains one append-only file `workspaces/<id>/tool-trace.jsonl`. It is written only by the host through a new trusted store method, `appendToolEvent`.
- Event: `{ sequence, tool, inputDigest, outcome, errorCode?, returnedSourceRanges[], contentBearing, receiptId?, artifactId?, latencyMs }`.
- `contentBearing` is true only for `search_transcript`, `inspect_segment` and `preview_range` results that returned transcript text or media. This is Proposal 001's rule. `get_timeline`, `get_task` and edit receipts are never content-bearing.
- Inputs are stored as digests, not text. Notes text is not copied into the trace.
- Like `attempts.jsonl`, the trace is never read for state.

## Submission and evaluation (F7–F10)

**Submit.** The `submit` tool, or budget exhaustion, or timeout, calls the M3 `freezeSubmission`. The host then renders a delivery preview of the frozen head and returns the frozen ref. A failed render is recorded as `render_failed`, not hidden.

**Evaluation runner (trusted, `@aether/harness/evaluation`).**
- Runs only after **all** paired submissions are frozen.
- For each, it reads exactly:
  - the frozen head snapshot;
  - its delivery `RenderManifest`;
  - the visible task;
  - the source/transcript hashes.
- It never reads traces, notes, contracts, plans, dialogue or arm identity (blind; parent plan).
- Results are written under `<evaluationRoot>/<runId>/results.json`, separate from any project store (F9). That root is never passed to a tool host.
- Results are hashed and **frozen** before diagnostics run.

**Evaluator (`evaluateSubmission`, pure, deterministic).**

| Check | Rule | Status |
| --- | --- | --- |
| `duration` | Measured delivered duration within `spec.targetDuration`. If it is within the delivery tolerance (one video frame plus one AAC frame) of a boundary, the result is `review`. | pass / fail / review |
| `retention:<criterionId>` | The union of final-timeline source coverage fully covers every `referenceRange`, using half-open overlap rules | pass / fail |
| `semantic:<rubricId>` | No semantic judge in M5 | review |
| `all_hard_criteria` | Primary metric: duration pass **and** every retention pass. `review` if any of these is `review`. | pass / fail / review |

Results use the existing `EditorialVerificationResultSchema`, with `evaluatedContentHash` = the frozen hash. Mechanical timing checks from M4 are mapped to `MechanicalVerificationResultSchema` and reported separately, never mixed with editorial results (parent plan).

**Diagnostics (`diagnose`, Proposal 001 P1).** This runs after results are frozen, reads traces, notes and (optionally) AETHER plans, and writes a separate `diagnostics.json`. For each failed retention criterion it assigns exactly one stage, using the rules in research.md:
- **`not_retrieved`:** no content-bearing trace event returned a range overlapping a `referenceRange`.
- **`retrieved_not_kept`:** one did, but no durable intent named it kept.
- **`intended_not_executed`:**
  - for **AETHER**: an EditorialPlan `selectedSegments` entry overlaps the reference;
  - for **notes**: a notes entry contains a segment ID whose range overlaps the reference. This is a deterministic rule: segment IDs only, no free-text matching, which is an asymmetry to report.

The rules are versioned (`diagnostics.v1`). Diagnostics never modify results and never reach agents.

## Noninterference (F11)

The test EvaluationSpecs embed sentinel strings, for example `SENTINEL-GOLD-7f3a` in IDs, descriptions and rubric text. A scripted session then runs every tool, including errors, and the tests assert:
1. No sentinel appears in any tool output, error message, trace line, attempt line, artifact manifest or notes file.
2. Running the identical scripted session against two **different** specs gives byte-identical tool outputs and traces (only `latencyMs` is masked).
3. A valid edit that removes the gold caveat **succeeds mechanically**, is graded `fail` offline, and causes no retry or feedback.
4. The tool host's module closure cannot reach `evaluator` or `diagnostics`. This is the AST import test, extended to `@aether/harness`.

## Scripted agents (F12)

Two deterministic scripted agents live in tests only:
- **`scriptedBaseline`**: searches, inspects, cuts repetition with ripple deletes, writes notes, previews and submits.
- **`scriptedCaveatDropper`**: the same, but deletes the caveat segment.

They prove interface equivalence and grading behaviour, not H1.

## Decisions requiring approval

| ID | Decision | Why |
| --- | --- | --- |
| F1 | New trusted `@aether/harness` package for tool dispatch and the evaluation runner. `@aether/tools` holds only agent-visible schemas. | `tools → workspace → tools` would be a dependency cycle. It keeps the agent-visible surface a pure schema package and gives trusted runtime code one home, which is the V0 precursor of the editor's command registry (LLD §7). |
| F2 | One host per workspace. `workspaceId` is kept in inputs for parity but must equal the bound ID. | An agent cannot reach another arm's workspace or the accepted head. |
| F3 | One frozen `ToolLimits` object for all arms, recorded per run. Budget exhaustion auto-submits. | Identical capabilities (AGENTS.md); unsuccessful outcomes are kept. |
| F4 | Lexical deterministic search only. | No gold-informed ranking; reproducible. |
| F5 | `preview_range` returns text + measured timing, not media. | V0 tool surface is text; equal for all arms. Multimodal is a later symmetric decision. |
| F6 | Trace file per workspace, written only by the host; inputs as digests; returned ranges recorded. | Proposal 001 needs content-bearing reads. Digests avoid copying model text. |
| F7 | Evaluator is pure over frozen data. Semantic → `review`. Duration borderline → `review`. | Parent plan; deterministic and auditable. |
| F8 | Diagnostics in a separate trusted subpath, run only after results are frozen and hashed. | Proposal 001 P1 isolation order. |
| F9 | Evaluation outputs live under a separate root (`.aether/evaluations/<runId>/`), never under `projects/`, never given to a host. | Matches the parent layout; keeps agent-reachable storage free of grades. |
| F10 | `submit` = M3 freeze + delivery render. Render failure is recorded, not retried by the evaluator. | Parent: freeze before grading; no grading-driven repairs. |
| F11 | Sentinel and differential noninterference tests are acceptance gates. | Parent: "accidental model-context/tool exposure is an acceptance failure". |
| F12 | Scripted agents live in tests only; no model SDKs or network. | M5 is a seam milestone; live models are a later, separately approved plan. |

## Acceptance tests

1. **Schemas.** Every tool input and output schema is strict. Unknown fields are rejected without echoing them.
2. **Binding.** A wrong `workspaceId` gives `workspace_mismatch` on every tool. No tool can name another workspace, a path, a preset or a binary.
3. **Timeline/task.** Pagination is correct. Gaps and duration are correct. Locks are shown as ranges only.
4. **Search.** It is deterministic: same query, same bytes. The ranking rule and tie-break are tested. Limits are enforced. The cursor is stable across calls.
5. **Inspect.** Context is bounded and neighbouring cues are correct. The on-timeline flags follow edits.
6. **Preview.** Text is in timeline order and matches the clips. Timing comes from the M4 manifest. The range is bounded. No path appears in the output.
7. **Edits.** Results are identical to calling the store directly. Replayed batches still count toward the budget.
8. **Budget.** Exhaustion auto-submits, records `budget_exhausted`, and every later call returns `budget_exhausted`.
9. **Trace.** Every call is traced. The content-bearing flag follows the Proposal 001 rule. Inputs appear only as digests.
10. **Evaluator.**
    - duration pass, fail and review at the boundaries;
    - retention with split children and redundant coverage;
    - a caveat removed by a valid edit → `fail`;
    - semantic → `review`;
    - all-hard-criteria truth table.
11. **Runner blindness.** The runner refuses to start until all submissions are frozen. Results are identical whether traces, notes or plans are present or deleted. Results are hashed before diagnostics.
12. **Diagnostics.** Each of the three stages is produced by a constructed scenario. Running diagnostics does not change the results hash.
13. **Noninterference.** The four F11 assertions.
14. **Scripted agents.** Both complete through the same host. The caveat dropper is mechanically valid and graded `fail`. Nothing is retried.
15. **Existing suite.** All prior tests still pass.

## Risks

- **Notes asymmetry in diagnostics.** Segment-ID matching under-counts free-text intent in notes. This is reported as Proposal 001 requires, not imputed.
- **Preview cost.** Each preview is a real render, about 1–4 s per FFmpeg launch on the Windows dev machine. Budgets count calls, not time; wall-clock is recorded.
- **Scope creep.** Prompts, model adapters and the compiler are explicitly excluded.

## Stop condition

Implement only after owner approval of this plan, including F1–F12. Stop after Milestone 5 is implemented, validated locally and on CI, recorded, committed and pushed.

## Implementation record — 2026-10-15

Approved by the owner on 2026-10-15 ("approve M5"). Implemented by the lead agent on branch `m5-tools-evaluator`, which builds on `m4-media`. Packets HS-01 and HS-02 were not delegated.

**What was built**
- `@aether/tools` (agent-visible): `contracts.ts` holds the nine tool names, strict input and output schemas, `ToolLimits` with defaults, and the tool error schema. It is schemas only, with no runtime dependencies beyond Core and Zod.
- `@aether/harness` (new, trusted):
  - `createToolHost`: one host per workspace, frozen limits, budget, auto-submit, and a trace of every call;
  - `./evaluation`: `runEvaluation` (frozen-only, blind, write-once `results.json` plus `results.sha256`) and `runDiagnostics` (checks the results hash, writes `diagnostics.json`).
- `@aether/verification/evaluator`: `evaluateSubmission` (duration with a review band, retention coverage, semantic → review, all-hard-criteria) and `coversRange`.
- `@aether/verification/diagnostics` (new trusted subpath): `diagnose` with `diagnostics.v1` rules.
- `@aether/workspace` store gains `readTask`, `readSafety`, `appendToolEvent` and `readToolTrace`, plus `ToolEventSchema`.

**Deviations (lead decisions)**
1. **Rule precedence in diagnostics.** The order is: `not_retrieved` (no content-bearing read overlapped), then `intended_not_executed` (durable intent overlapped), then `retrieved_not_kept`. research.md gives three conditions without a precedence. This order means intent recorded without any retrieval still counts as `not_retrieved`.
2. **No separate per-call timeout.** Only rendering has a timeout, inherited from M4 media options. The other tools are bounded local reads.
3. **Tool-call limit default is 60** (`DEFAULT_TOOL_LIMITS.maxToolCalls`). Experiment runs take it from `ExperimentConfig.budget.maxToolCalls`.
4. **Delivered duration** for grading is the delivery render's measured video duration (exact frame count × 40 ms). Audio drift is reported separately as a mechanical check.
5. **The trace records the tool name as `unknown`** when an agent names an unknown tool, so agent-chosen strings are not copied into traces.
6. **Evaluation results include the run ID and spec ID.** The blindness test therefore compares the per-submission results rather than file hashes.

**Observed results**
- Four scripted agents ran through identical hosts:
  - baseline: all hard criteria pass;
  - caveat-dropper with notes: `intended_not_executed`;
  - caveat-dropper without notes: `retrieved_not_kept`;
  - blind deleter: `not_retrieved`.
  Each dropper's edits were mechanically valid and graded `fail` offline, with no retry.
- **Noninterference.** Sentinel strings in two different specs never appear in any store file, tool output or trace. The two sessions produced byte-identical tool outputs and traces (latency masked), even though a different spec had been evaluated beforehand in each.
- **Blindness.** Deleting all traces and notes leaves the evaluator's per-submission results identical.

**Tests:** 13 new (12 in `tests/harness.test.ts`, one harness boundary test). The exports check for `@aether/tools` was updated to list the new schema exports; the hidden evaluator schemas are still absent from it.
