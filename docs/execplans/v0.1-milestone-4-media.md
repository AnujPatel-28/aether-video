## Purpose and observable outcome

After this milestone, a trusted local owner process can:

- check that FFmpeg and ffprobe are present and record their versions (preflight);
- ingest one controlled 25 fps / 48 kHz source video plus a timestamped transcript into a new project store: content-addressed source copy, probe record, normalized transcript, stable segments and the initial full-source ProjectIR;
- reject unsupported sources explicitly, with a typed reason;
- render a preview of any workspace head, or any frame-aligned range of it, with a fixed preset, and store it as an immutable artifact bound to the content hash it shows;
- prove with decoded frames and samples that rendering is exact: no timing drift across 1, 10 or 100 edits.

Agents still cannot choose an executable, a path, a filter, a codec or a shell string. They gain no tools in M4; tool dispatch is M5.

## Verified technique (2026-10-15, FFmpeg 9.0.1, Windows)

A spike in the scratchpad confirmed the core test method:

- **Video marker.** `geq=lum='mod(N,256)'` stores each frame's index in its luma. FFV1 is lossless, so decoding gives the exact index back.
- **Audio marker.** `aevalsrc=exprs='n/576000'` stores each sample's index as a float. `pcm_f32le` is lossless, so decoding gives the exact index back.
- **Exact cuts.** `trim=start_frame/end_frame` and `atrim=start_sample/end_sample`, each followed by `setpts`/`asetpts=PTS-STARTPTS`, then `concat`, cut on integer frames and samples. There is no millisecond rounding in the recipe.
- **Spike result.** Two segments (frames 50–59 and 10–14) decoded to exactly `50…59, 10…14`. Audio decoded to samples `96000…115199` then `19200…28799`: 28,800 samples, which is 15 × 1,920.

This makes exact verification possible: every output frame and sample can be checked against the source position it should come from.

## Storage layout additions

```text
<storeRoot>/projects/<projectId>/
  assets/<sourceHash>                # immutable byte copy of the source; no extension
  ingestion.json                     # IngestionRecord (probe facts, binary versions, hashes)
  transcript.json                    # NormalizedTranscript (ms cues, digest)
  artifacts/<artifactId>/
    manifest.json                    # RenderManifest; written last (artifact commit point)
    media.mkv | media.mp4            # rendered output
```

- Artifacts are immutable and content-addressed: `artifactId = "artifact-" + sha256({ domain, contentHash, range, presetId, binaryVersions })`.
- A directory without `manifest.json` is an orphan and is ignored.
- Rendering never changes `head.json` or `accepted-head.json`.
- The parent plan puts `artifacts/` under the project, so this plan keeps it there. Every artifact is shared and keyed by content: two workspaces with the same head reuse one artifact.

Unsupported-source reasons are a closed list: `vfr`, `frame_rate`, `audio_rate`, `stream_ambiguous`, `rotation`, `hdr`, `duration_contradiction`, `av_mapping`, `not_on_grid`.

## Operations and exact semantics

### Preflight
- Resolve binaries from the `AETHER_FFMPEG` and `AETHER_FFPROBE` environment variables if set, otherwise from `PATH`.
- Run `-version` through `spawn` with an argument array and `shell: false`. Record the first version line.
- If a binary is missing, return `ffmpeg_missing`.
- Media tests treat a missing binary as a **failure, never a skip** (parent plan).

### `probeSource(path)`
1. Run ffprobe with fixed arguments: `-v error -print_format json -show_streams -show_format`, plus a packet pass `-select_streams v:0 -show_entries packet=pts_time,duration_time`.
2. Video checks:
   - exactly one video stream;
   - at most one audio stream;
   - `r_frame_rate = avg_frame_rate = 25/1`;
   - **every** packet PTS step is exactly 40 ms (CFR proven from timestamps, not from the average);
   - rotation is 0;
   - transfer is not PQ/HLG.
3. Audio checks: 48 kHz, and the sample count equals `frameCount × 1920` within one audio codec frame. If it doesn't, the reason is `av_mapping`.
4. Presentation origin is the first video PTS. Audio may start at the same PTS or a recorded offset. Relative offsets are kept (parent §ingestion 3).
5. There is no transcoding. If any check fails, the result is `unsupported_source` with its reason.

### `importTranscript(bytes)`
- Input is UTF-8 JSON in the parent schema.
- Times are converted once to integer milliseconds with nearest rounding, ties going earlier (consistent with frame alignment).
- Cues that are unordered, empty, overlapping or outside the source duration are rejected. Gaps are legal.
- Segment ID: `segment-` + sha256({ domain `aether.segment.v1`, assetId, transcriptDigest, cueIndex, startMs, endMs }).

### `ingestProject(storeOptions, { sourcePath, transcriptPath, projectId, safety })` (workspace)
1. Preflight, probe, then transcript import. Any failure returns a typed error with no files written.
2. Hash the source bytes and copy them to `assets/<hash>` using temp-then-rename. The user's file is opened read-only and never modified.
3. Write `transcript.json` and `ingestion.json`.
4. Build the full-source ProjectIR (one clip covering `[0, frameCount × 40)`), then call the M3 `initProject` path. `accepted-head.json` is still the single commit point. Anything written before it is an orphan if the process crashes.
5. Ingestion never reads EvaluationSpec. No locks are inferred.

### Render recipe compiler (pure; `compileRecipe(project, range, preset)`)
- Input: a validated ProjectIR snapshot, a frame-aligned timeline range (default: the full sequence) and a preset.
- The timeline is turned into an ordered list of **segments**: clip pieces cut by the range, plus black/silence gaps.
- Each clip piece becomes `trim=start_frame:end_frame` and `atrim=start_sample:end_sample`, where `start_sample = start_frame × 1920`. All arithmetic is in integer frames.
- Gaps become `color=black:s=WxH:r=25:d=…` and `anullsrc=r=48000`, trimmed to exact frame and sample counts. A source with no audio is given synthesized silence.
- One `concat=n=K:v=1:a=1`.
- Output is `{ args: string[], expected: { frames, samples } }`.
  - The filter graph is passed with `-filter_complex` as a single argument. There is no shell.
  - A hard cap of 400 segments is enforced (100-cut tests use about 201). Above the cap: `render_out_of_bounds`.
- Presets are closed:
  - `test-lossless-v1`: FFV1 + `pcm_f32le` in Matroska, `-threads 1`.
  - `delivery-h264-v1`: libx264 (`-preset medium -crf 18 -pix_fmt yuv420p -threads 1`, keyint 25) + AAC 48 kHz 128 kb/s in MP4, `+faststart`.
- Agents and callers never provide arguments. Only the preset enum crosses the boundary.

### `renderPreview(workspaceId, request)` (workspace)
1. Load the workspace head snapshot (M3 verification) and require `request.contentHash === head.contentHash`, so stale evidence cannot describe a newer head.
2. Align the range with the existing Core `alignTimeMs` and record requested and effective values.
3. If an artifact with the same `artifactId` and a valid manifest exists, return it (idempotent).
4. Compile the recipe, run FFmpeg into a temp file in the artifact directory, then measure the output with ffprobe. For the lossless preset, also decode and check the markers.
5. Write the media, then `manifest.json` last.
6. Rendering works in any workspace state (open, frozen, committed), because it only reads.

### Measurement and mechanical checks
- **Lossless preset:**
  - decoded frame count and sample count must equal `expected` exactly;
  - in tests, marker media also proves the order and origin of every frame and sample.
- **Delivery preset:**
  - `|measured video duration − nominal| ≤ 40 ms`;
  - `|measured audio duration − nominal| ≤ 40 ms + one AAC frame (1024/48000 s ≈ 21.3 ms)`, after the declared encoder priming is removed;
  - the A/V offset is recorded.
  - This is the parent plan's global bound: one video frame plus one encoded audio frame, **not** multiplied by the number of edits.
- If a check fails, the result is a `timing_mismatch` mechanical check with status `fail` and its evidence. A preview never returns editorial scores.

| ID | Decision | Why |

| E1 | `@aether/workspace` depends on `@aether/media`; media never depends on workspace. Ingestion and preview are workspace lifecycle commands, and media is a library of pure functions plus subprocess calls. | Keeps one owner of the store layout (M3) and gives media no store or mutation authority, matching the parent's package table. | E2 | Binaries come from `AETHER_FFMPEG`/`AETHER_FFPROBE`, otherwise `PATH`. Versions are recorded in every ingestion record and manifest. The tests compare decoded timing, not bytes (parent plan), so pinning one build is unnecessary. Version differences are visible in records. |
| E3 | Test media is generated by FFmpeg at test time (marker video and audio, 160×90, 12 s / 300 frames, plus variants). Nothing binary is committed. | Deterministic, small and reviewable. The parent asks for a fixture long enough for 100 distinct cuts. |
| E4 | All recipe arithmetic uses integer frames and samples (`trim start_frame`, `atrim start_sample`). Milliseconds exist only at the API boundary. | Verified in the spike. Rounding cannot accumulate because nothing is rounded after alignment. |
| E5 | The filter graph is passed inline as one argument, with a 400-segment cap. | No script files or deprecated `-filter_complex_script` flag (its spelling differs between FFmpeg 6 and 9). The cap keeps the command under the Windows 32 KiB limit. |
| E6 | Two closed presets only: `test-lossless-v1` and `delivery-h264-v1`. The delivery bound is one video frame plus one AAC frame. | Parent plan: a lossless test preset for exact checks and a delivery check against a global bound. |
| E7 | Artifacts live in `projects/<id>/artifacts/<artifactId>/`, content-addressed, with `manifest.json` written last as the commit point. Rendering never touches workspace or accepted heads. | Same commit-point discipline as M3. Reuse across identical heads. Orphan temp files are ignored. |
| E8 | The source is probed and verified, never transcoded. Unsupported input fails with a closed reason list. | Parent plan: "do not silently transcode uncontrolled sources into experimental fixtures". |
| E9 | CI adds an `apt-get install -y ffmpeg` step (Ubuntu 24.04 package) before tests, and prints `ffmpeg -version`. No other workflow change. | Media acceptance needs real binaries on CI. A missing binary fails, never skips. |
| E10 | The render runner has a timeout (60 s per render in tests, configurable by the trusted caller) and kills the process tree when it expires. | A hung FFmpeg must not hang CI. The result is `render_failed` with reason `timeout`. |

There are no new npm dependencies. FFmpeg and ffprobe are external binaries, as the parent plan already specifies.

## Acceptance tests

Pure tests (no FFmpeg) run first. Media tests need FFmpeg and **fail** if it is missing.

1. **Preflight.** It reports versions. An invalid `AETHER_FFMPEG` path gives `ffmpeg_missing`.
2. **Probe accepts the controlled profile.** Results are exact: 300 frames, 576,000 samples, origin 0. A non-zero origin (`-output_ts_offset`) is accepted and recorded, and A/V offsets are kept.
3. **Probe rejects** each variant with the right reason:
   - 30 fps → `frame_rate`;
   - jittered PTS → `vfr`;
   - 44.1 kHz → `audio_rate`;
   - two video streams → `stream_ambiguous`;
   - rotation metadata → `rotation`;
   - a 1,000-sample audio shortfall → `av_mapping`.
4. **Transcript import.** Seconds and milliseconds both work, and ties round earlier. Unordered, empty, overlapping and out-of-range cues are rejected. Gaps are allowed. Segment IDs are deterministic and change if the digest or a range changes.
5. **Ingestion.**
   - The asset is byte-identical to the source, and the user's file is unchanged (hash before and after).
   - ProjectIR validates with one full clip.
   - A crash at every write position leaves either no project or a complete one (M3 fault wrapper).
   - Re-ingesting gives `already_exists`.
   - Ingestion is identical whether or not an EvaluationSpec exists on disk.
6. **Recipe compiler (pure).**
   - Frame and sample expectations are exact for gaps, reordering, a range that cuts through clips, an empty range, and a source without audio.
   - Above 400 segments: `render_out_of_bounds`.
   - Arguments contain no caller-provided strings: property test over random timelines.
7. **Exact lossless render.** Decoded markers equal the expected `(frame index, sample index)` sequence for:
   - the full source;
   - a split;
   - a trim;
   - a reorder;
   - gaps (black luma 0 / silence 0.0);
   - a sub-range preview;
   - a no-audio source (synthesized silence).
8. **Accumulation.** 1, 10 and 100 cuts, each with repeated off-grid requested times. Decoded totals are exact (lossless), and the delivery preset stays within the global bound **for every count**: the error does not grow.
9. **History equivalence.**
   - Split followed by render keeps the total frame count.
   - Split, undo, then render equals the original render (lossless decoded markers).
   - Two different histories with the same `timelineContentFingerprint` give identical decoded markers.
10. **Artifacts.**
    - The same request twice gives one artifact (idempotent).
    - A stale `contentHash` is rejected.
    - A crash before `manifest.json` leaves an orphan that is ignored and re-rendered.
    - Rendering changes no head, receipt or snapshot (M3 `tree` comparison).
11. **Boundaries.**
    - No agent-reachable input reaches the `args` array except through the preset enum and aligned integers.
    - Media imports only Core, Zod and Node built-ins.
    - Workspace's allowed imports add `@aether/media` only.
    - The evaluator is still unreachable.
12. **Timeout.** A recipe forced to hang (test-only `-re` on a long input with a 1 s timeout) gives `render_failed`/`timeout` and leaves no running process.
13. **Existing suite.** All 124 prior tests still pass.

## Risks

- **FFmpeg version differences** (9.0.1 locally, 6.x on Ubuntu 24.04). Mitigated by decoded-timing comparison (E2), avoiding version-specific flags (E5), and running CI on every push.
- **AAC priming and padding** differ between encoders. The delivery check removes the declared priming and records offsets. If the bound fails on CI's encoder, the preset is revised before any experiment (parent plan). The tolerance is not loosened.
- **Test runtime.** About 40 short renders at 160×90. The estimate is under 60 s; the CI timeout stays at 10 minutes.
- **Scope creep toward the editor.** Proxies and waveform peaks are V1, not M4.

**What was built**
- `@aether/media`:
  - `schemas.ts`: transcript, probe, ingestion, render request and manifest, timing checks, typed `MediaError`.
  - `process.ts`: `runProcess` (`spawn`, `shell: false`, timeout kill, bounded output), `resolveBinaries`, `preflight`.
  - `probe.ts`: CFR proven from every packet timestamp.
  - `transcript.ts`: transcript import, segment IDs, `buildInitialProject`.
  - `recipe.ts`: pure `planSegments`, `compileRecipe` and `renderArgs`.
  - `render.ts`: render runner, measurement, timing checks, file digest.
  - Dependencies: `@aether/core` and `zod` only.
- `@aether/workspace`:
  - `ingestProject` shares the M3 creation path through `createProject`, with `accepted-head.json` still the single commit point;
  - `ProjectStore.renderPreview` with content-addressed artifacts whose `manifest.json` is written last;
  - `StoreFs` gains `rename` and `copyFileAtomic`.
- CI installs FFmpeg from Ubuntu 24.04 packages and prints its version (E9).

**Deviations (lead decisions)**
1. **Container duration.** Matroska reports the end time, not the span, so the check accepts either `duration` or `duration − origin`, within one video frame plus one audio codec frame.
2. **A/V start.** Audio must start exactly at the video presentation origin. A non-zero *common* origin is supported and tested (2 s). A relative A/V offset is rejected as `av_mapping` rather than preserved. This is narrower than the parent plan; it can be revisited if real sources need it.
3. **Audio length.** No shortfall is allowed: every video frame needs its 1,920 samples. Excess must be under one codec frame plus one video frame. The variant tested is a 0.2 s shortfall instead of 1,000 samples, because any shortfall is now rejected.
4. **New unsupported reason `audio_layout`.** Only mono or stereo is accepted.
5. **Timing results use a media-local `TimingCheck` schema,** not `MechanicalVerificationResult`. Media and workspace must not depend on `@aether/verification`; M5 maps one to the other.
6. **New `WorkspaceError` codes:**
   - `media` (wraps `MediaError`);
   - `media_unavailable` (a project created without ingestion);
   - `stale_content` (a render request for a hash other than the head's).
7. **`preflight` is cached per binary pair for the life of the process.** Windows launches of the 222 MB FFmpeg build take 1–4 s each.
8. **CI timeout raised from 10 to 15 minutes** for the FFmpeg install and media tests.
9. **Test changes:**
   - group 6's "no caller strings" property is checked as a fixed filter-graph grammar over 50 random timelines;
   - group 12 uses a non-terminating `runProcess` and a 1 ms render timeout instead of an `-re` recipe;
   - gap frames are identified by equal top and bottom luma below the marker range, whatever value black takes in the source pixel format.

**Observed results (Windows 11, FFmpeg 9.0.1 gyan.dev full build)**
- Every lossless render decoded **exactly**: each frame's index and every sampled audio index matched the expectation, with continuous audio inside each frame. This covered:
  - the full source;
  - a split;
  - a trim, a delete and a move together;
  - a sub-range with off-grid endpoints (1013→1000, 6020→6000);
  - a no-audio source.
- **Accumulation.** At 1, 10 and 100 off-grid cuts, plus ripple deletes and a reorder, lossless output stayed exact and the delivery output passed both duration checks with an exact video frame count. The error did not grow with the number of edits.
- **History.** A split render decodes identically to the unsplit original (same fingerprint, different artifacts). Split then undo reuses the original artifact.
- **Ingestion crash test.** A crash at every write position left either no project or a byte-identical complete one.
- **Known limit, not exercised.** The single-input filter graph buffers decoded frames of segments that are reordered earlier. That is fine for talking-head shortening and 12 s fixtures, but long reorders of long sources could use a lot of memory. Revisit before experiments if plans reorder heavily.
