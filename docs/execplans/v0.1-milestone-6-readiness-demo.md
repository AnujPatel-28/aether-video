## Purpose and observable outcome

After this milestone, one command shows that the whole foundation works end to end on generated media, with no model account and no network:

```text
pnpm --filter @aether/harness-cli demo:foundation
```

The demo:
1. generates controlled marker media and a transcript (M4 generator, moved from tests into a trusted CLI module);
2. ingests it into a fresh store under a temporary root;
3. forks paired workspaces and runs **two scripted adapters through identical tool hosts**:
   - a baseline-style adapter (notes, retrieval, recovery from one deliberate stale-revision error);
   - an "AETHER-shaped" adapter that writes a typed EditContract and EditorialPlan through a trusted artifact slot, then emits only shared operations;
4. shows **equal behaviour for equal operations**: when both adapters submit the same operations, they reach the same content hash and the same render timing;
5. shows isolated history: undo, redo and replay in one workspace leave the other workspace and the accepted head untouched;
6. renders and measures delivery output;
7. freezes, then runs blind offline evaluation and diagnostics, including an intentionally dropped unlocked caveat (the edit succeeds, grading fails, no repair follows);
8. writes a **run manifest** and **usage ledger** (below) and prints a short readiness report.

The report lists every check with pass or fail. The command exits non-zero if any check fails.

## Accounting (G3–G5)

**Run manifest** (`<evaluationRoot>/<runId>/manifest.json`, trusted). It records:
- project, source and transcript hashes;
- task and safety hashes;
- tool-limit hash;
- tool, kernel and evaluator versions (`evaluator.v1`, `diagnostics.v1`);
- render presets and FFmpeg versions;
- a model block (`{ provider: 'scripted', modelId, version }` in M6);
- sampling;
- the prompt-construction rule (research.md: neither arm preloads the full transcript);
- condition mapping, trusted only and kept apart from submissions;
- spec and evaluator hashes, trusted only.

**Usage ledger** (`ledger.jsonl` per workspace, append-only, written by the host). Event kinds follow the parent plan's instrumentation table:
- `model`: stage, request/response digests, input/output/cache/reasoning tokens, latency, billed cost. Unavailable values are recorded as `null` with an availability flag, never as 0.
- `tool`: already in the M5 trace; the ledger references it by sequence.
- `runtime`: stage wall time, compiler CPU/wall time, render time.
- `submission`: outcome (`submitted | budget_exhausted | timeout | render_failed`).

In M6 the scripted adapters emit **synthetic model events**, so the accounting path is exercised end to end.
- Replayed or deduplicated tool requests count once as a request, and are marked `replayed`.
- Failed model responses are recorded, not dropped.

**Budget enforcement extends to tokens.** The host refuses further model-stage events once `ExperimentConfig.budget.maxTokens` is exhausted and auto-submits, as M5 already does for tool calls. Both arms share one budget object.

## Acceptance tests

1. `demo:foundation` exits 0 locally and on CI, and every report check passes.
2. **Equal operations give equal results:** the same hash, the same timing and the same tool outputs (latency masked) across both adapters.
3. **Isolation:** undo, redo and replay in A leave B and the accepted head byte-identical.
4. **Caveat drop:** mechanically valid, graded `fail`, diagnostics stage reported, and no repair call after freeze.
5. **Ledger:**
   - every model and tool event is present;
   - replayed requests are counted once and flagged;
   - unavailable usage is `null` plus a flag;
   - token exhaustion auto-submits.
6. **Manifest** contains every field listed above. Trusted-only fields never appear under `projects/` (sentinel scan as in M5).
7. **Artifact slot:** invalid contracts and plans are rejected; the evaluator never reads them; diagnostics uses the plan's `selectedSegments`.
8. All prior tests pass.

## Implementation record — 2026-10-15

Approved by the owner on 2026-10-15 ("approve M6"). Implemented by the lead agent on branch `m6-readiness-demo`, which builds on `m5-tools-evaluator`.

**What was built**
- `apps/harness-cli`:
  - `fixtures.ts`: the marker-media generator, moved from tests (G2); tests now re-export it.
  - `adapters.ts`:
    - the baseline-style adapter: retrieval, notes, a deliberate `stale_revision` it recovers from, and an exact retry that is deduplicated;
    - the AETHER-shaped adapter: contract → plan → compiled shared operations;
    - synthetic model events.
  - `demo.ts`: `runFoundationDemo`, 14 named checks.
  - `cli.ts`: `pnpm --filter @aether/harness-cli demo:foundation` writes `readiness-report.json` and exits non-zero on any failure.
- `@aether/harness`:
  - host token budget, `recordModelEvent` and `recordRuntime`;
  - a ledger entry for every tool call (with the `replayed` flag) and every submission;
  - `./orchestration`: `writeContract`, `writePlan`, `readContract`, `readPlan` (G6);
  - `./evaluation`: `RunManifestSchema`, `writeRunManifest`, `hashJson` (G3).
- `@aether/workspace`:
  - `LedgerEventSchema`, `appendLedgerEvent`, `readLedger` (G4);
  - `writeOrchestrationArtifact` / `readOrchestrationArtifact`: opaque JSON, open workspaces only.
- CI runs the demo after the tests (G8).

**Deviations (lead decisions)**
1. **Artifact slot path** is `workspaces/<id>/orchestration/{contract,plan}.json`, not `artifacts/`, so it can't be confused with the M4 render artifacts.
2. **The shared tool surface changed symmetrically:**
   - `ToolLimits` gains `maxTokens` (default 200,000);
   - `get_timeline` now returns the sequence `assetId`, so typed contracts can cite source references using only tool-visible information.
   - Both apply identically to every arm.
3. **What counts toward the token budget:** input + output + reasoning tokens. Unavailable counts are recorded as `null` but count as 0 toward the budget. **Before live experiments,** a provider that does not report usage must be handled, for example by local token estimation recorded as an estimate.
4. **Plans must match the current head.** `writePlan` requires `baseContentHash` to equal the workspace head, and `writeContract` requires the bound task's ID.
5. **Equal-operations comparison** masks only receipt IDs, which hash the workspace ID by design. Everything else, including preview timing, is byte-identical.
6. **One invalidation counter.** Ledger and trace append failures share `traceFailures()`, and either invalidates a trial's accounting.

**Observed results (Windows)**

- Both scripted arms reach the same timeline schedule.
- Offline grading: baseline pass, AETHER pass, caveat-dropper fail with diagnostics stage `intended_not_executed`.
- Grading causes no repair after freeze.
- Token budget: auto-submitted at 3,800 tokens with a 2,000 limit.
- 90 agent-reachable files scanned with no sentinel found.

**Tests:** 3 new in `tests/readiness.test.ts` (the full demo, the artifact slot, ledger and manifest strictness). The harness boundary test now expects the `./orchestration` export.
